CAUSA RAIZ — src/components/public/JobApplicationForm.jsx:44-54:

  const [vaga, setVaga] = useState(undefined);  // undefined = loading
  ...
  const { data, error: err } = await supabase.rpc("get_vaga_publica", {...});
  if (err || !data || data.length === 0) { setVaga(null); return; }

Dois problemas distintos no mesmo trecho:

  (a) SEM TIMEOUT. Se a promessa não resolve (rede lenta, 3G ruim, backend
      pendurado), `vaga` fica `undefined` e o spinner é permanente. O
      supabase-js não impõe timeout por padrão.
  (b) ERRO DE REDE = "VAGA NÃO ENCONTRADA". Quando a chamada FALHA, o código
      cai no mesmo `setVaga(null)` usado para "slug inexistente". O candidato
      em rede instável recebe a informação de que a vaga não existe — e ela
      existe. Ele não tenta de novo.

Onde isso dói mais: é a porta de entrada de recrutamento. A pessoa que você
quer contratar chega por celular, em rede móvel, e vê um spinner eterno ou uma
mensagem errada dizendo que a vaga acabou.

CORREÇÃO:
  1. Separar os três estados: carregando / erro de rede / não encontrada.
     `const [erro, setErro] = useState(null)` e distinguir `err` de
     `data.length === 0`.
  2. Timeout de ~10s com mensagem "Não conseguimos carregar agora" + botão
     "Tentar de novo".
  3. Aplicar o mesmo em PesquisaPublicaForm.jsx e BemEstarPublicaForm.jsx —
     é o mesmo padrão nos três.
